1. Reconciliation — What This Addendum Adds and Why

The original Microservices-Implementation-Guide reconciled a short "Volume 9" outline into 7 services plus a backlogged Marketplace Engine. This new source, read in full, adds four engine families that outline never named at build-detail level:

Scope discipline check: these are new Tier 2 surface, same tier as Workflow/Safety/Governance. Build order matters more than completeness — ordered below by dependency and by how directly they serve the platform's core economic claim (80% LLM-cost reduction, ADLC Plan §9), not by how the source happens to list them.

2. Updated Architecture Overview

Tier 1 unchanged · Tier 2 extended with 4 services · Tier 3 gains pgvector
  • Tier 1 (unchanged): Agent Registry, Trust Authority, Discovery Service, Memory Service.
  • Tier 2 (extended): Workflow Engine, Safety Engine, Governance Engine, Marketplace Engine (backlog) + Knowledge Service, Cost Optimiser Service, ML Integration Service, Verification Engine.
  • Tier 3 (extended): PostgreSQL, Redis, Neo4j, Kafka + pgvector on the existing PostgreSQL instance.

The dependency rule holds: no Tier 2 service calls another Tier 2 service synchronously — the new services communicate via Kafka events, same as Workflow/Safety/Governance already do.

4. Communication Patterns — Additions

4.1 Cost Optimiser — the one synchronous exception in Tier 2

Routing decisions must be available before an LLM call is made, so POST /route/decide is synchronous from the Gateway, budgeted at <20 ms. This is the only synchronous Tier 2 call in the system — if a second one gets proposed later, treat that as a signal to re-examine the tier boundary, not a precedent.

4.3 Cache/memory layer implementation, now canonical

Instructional Manual §3.5 built only L1 Session Cache, TTL = 1 hour as an explicit reduced-scope MVP. This addendum extends to the full model resolved in ADLC Plan §15.3, TTLs pinned by this source's Sprint 2.2 spec:

LayerScopeTTL
L0 Prompt CacheExact-match prompt+context hash5 minutes
L1 Session CachePer-session (already built)1 hour
L2 Agent CachePer-agent, cross-session24 hours
L3 Workflow CachePer-workflow-definition reuse7 days
L4 Organisation CacheCross-agent, per-organisation30 days
L5 Federation CacheCross-organisationPolicy-controlled (Governance Engine decides per call)

6. Confidence Bands — Verification Engine

Reuses the exact band structure the source repeats consistently across every pass — one of the few things that didn't drift between drafts:

CONFIDENCE_BANDS = [(95, "GREEN"), (80, "AMBER"), (60, "RED"), (0, "GREY")]
# GREEN=Verified, AMBER=Inference, RED=Challenge, GREY=Risk

This feeds the same {answer, confidence, evidence[], verification_status} contract Safety Engine already returns — a deeper pipeline with a real truth score, not a competing contract.

7. Definition of Done — Microservices v2 Milestone

  • Knowledge Service, Verification Engine, Cost Optimiser Service, and ML Integration Service all report "status": "ok" on /health.
  • Cache Service serves all six layers (L0–L5) with the TTLs above; an L5 policy-denied request returns a clear reason, not a silent fallback.
  • POST /route/decide responds in <20 ms p95 with an explainable Utility Score breakdown.
  • A workflow completion produces a real verification.completed event, consumed by ML Integration Service within 1 second.
  • Recorded in governance/decisions/, noting Marketplace Engine and connector layers remain backlog.
