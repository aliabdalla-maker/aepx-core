1. Reconciliation — How This Source Relates to the Existing Plan

What this document is. Unlike the prior "Volume 9" outline source, this attachment is the full escalating draft chain itself — Executive Vision → PESTEL → SPARC-Native Lifecycle → Universal Plug and Connect Framework → "V3 Standards Programme" → nine further "Stage"/"Programme" re-plannings climbing to increasingly aspirational scope (Autonomous Intelligence Internet, Agent Operating System, Planetary Intelligence Grid, "AEP-X Zero — Version ∞") → a ~10,000-line business/governance chain (PMO, HR, BCP, ESG, ISO roadmap, M&A, IPO/Exit, 20-year Legacy Framework) → a return to concrete Sprint 0–4 build specs and the full text of RFC-0001–0010 / RA-0001–0008. It is the "3,188-page consolidated edition" the ADLC Plan's Critical Evaluation (§15.2.8) already warned about — roughly 30 restart points, each ending "the next step is…", terminology drifting between passes.

Why an SOA document at all. The source never once uses the words "SOA," "service-oriented," or "ESB" — that framing is this engagement's, not the manual's. But the source does independently converge, repeatedly, on a Connector Contract naming exactly the protocol mix classic SOA/ESB architectures exist to mediate: Supports: MCP, REST, GraphQL, gRPC, MQTT, Kafka, NATS, SOAP, OPC-UA, Custom, plus a generic Connector interface (authenticate / discover / execute / monitor). The Universal Connector Layer — Enterprise (SAP, Salesforce, MS Dynamics, Oracle, Workday, ServiceNow), Industrial (SCADA, PLC, OPC-UA, Modbus, BACnet), Productivity (Google Workspace, M365, Slack, Teams, Zoom), Developer (GitHub, GitLab, Jira, Confluence, Azure DevOps), AI Platforms (OpenAI, Anthropic, Gemini, Mistral, Ollama, vLLM, HuggingFace) — is the one part of this source not well served by the microservices style already committed. This document designs that layer as SOA and leaves the AI-native core as microservices. See Hybrid-Architecture-and-Comparison.html for why the boundary sits there.

2. Why SOA Fits the Universal Connector Layer and Not the Core

Classic SOA/ESB architecture earns its coupling and mediation overhead when a system integrates with external systems it does not own, speaking heterogeneous, often legacy protocols, changing on vendor release cycles, requiring centralised governance before any AEP-X agent touches them. That is the Connector Layer's problem, not the AI-native core's:

PropertyAI-native coreUniversal Connector Layer
Who owns the target systemAEP-XExternal vendor / customer's estate
Protocol diversityOne (internal REST + Kafka)Many at once: SOAP, OPC-UA, proprietary RPC, REST, GraphQL, Modbus
Release cadenceContinuousVendor-controlled, 6–18 months
Independent-deploy unitOne microserviceUsually a whole protocol family at once
Governance requirementEnforced once, in Governance EngineEnforced per external system, often per regulator (AIA-R is per-connector)
Risk if built as N microservicesN/AN near-identical services each re-implementing auth/retry/audit — "distributed monolith of adapters"

Microservices optimise for independent deployability of cohesive capabilities you own. The Connector Layer is the opposite shape — many external protocols funnelling into one set of AEP-X-side concerns (trust check, policy check, canonical translation, audit). That's an Enterprise Service Bus's job description.

Architecture

3. SOA Architecture — the AEP-X Connector Bus (ACB)

5 coarse-grained connector services · 1 bus · shared trust & governance spine

3.1 Design principles

1

Coarse-grained services, fine-grained adapters. One connector service per category (5 services), not one per external system (25+). Inside each, one Connector implementation per system, reusing the source's own interface verbatim:

class Connector:
    async def authenticate(self): pass
    async def discover(self): pass
    async def execute(self, request): pass
    async def monitor(self): pass
2

Canonical message model, no exceptions. Every connector translates its external protocol into and out of the RFC-0001 envelope before touching the bus — the same envelope already used inside the microservices core.

3

Mediation, not choreography. The core's Tier 2 talks by publishing facts to Kafka (Microservices Guide §4.2). The bus does the opposite on purpose: it centrally orchestrates trust check → policy check → translation → route → external call → response translation, because that sequencing must be enforced before every call to an ungoverned external system, not eventually-consistent after it.

4

Contract-first per connector. Each publishes a Connector Contract naming its protocols, canonical message version, required governance checks, and assigned AI risk class.

5

No connector calls another connector. Cross-connector workflows go through Workflow Engine via the Gateway — the bus stays a mediation layer, not a second orchestrator (the "smart pipes, dumb endpoints" SOA anti-pattern).

3.3 The bus itself

connector-bus/ (repo root, a sibling of services/) — a single lightweight FastAPI mediation service plus the existing Kafka bus, not a commercial ESB product. POST /bus/route accepts an RFC-0001 envelope, checks trust and policy via the existing Trust Authority and Governance Engine APIs, forwards to the resolved connector, and publishes connector.invoked/connector.failed to the same Kafka bus Governance Engine already audits unconditionally.

4. Security & Compliance in the SOA Layer

Reuses everything already specified for the core — no new security model. OAuth2/OIDC + JWT for the calling agent; mTLS Gateway→Bus→connectors; Trust Before Execution (Law 2) enforced structurally at the bus, before any external system is touched; every call wrapped in the {answer, confidence, evidence[], verification_status} contract. AIA risk classification is assigned once per connector at onboarding — deliberately different from the S0–S4 safety classification, which is per call. Connectors touching Workday or any Industrial system default to AIA-R2+, requiring at minimum Silver assurance before going live.

6. Definition of Done — SOA Milestone

  • POST /bus/route rejects a call when trust is below the connector's threshold, visible in Governance Engine's audit log within 1 second.
  • At least one live connector per category except Industrial responds end-to-end through the full mediation chain.
  • Every connector call is audited with ai_risk_class and trust_score_at_call_time.
  • No connector service calls another connector service directly.
  • Recorded in governance/decisions/, noting Government/Education and Industrial connectors remain reference-design-only.
